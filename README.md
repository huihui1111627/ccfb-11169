# kitewheel — 风筝节延时消息调度

用分层时间轮做几十万条定时消息（入场提醒、退票截止、放飞场次提醒）的调度，
消息落盘可恢复，带一个可拨快虚拟时钟的调度台页面。

原来的数据库轮询在节前一晚几十万条同时到点时晚了二十分钟。这里的核心变化是：
调度结构本身不扫描数据库，到期瞬间的投递顺序由时间轮的各层格子和排序保证，
一次拨钟只处理真正有消息的格子，空格直接跳过。

## 运行

```bash
# 演示：内存库，30 万条消息 + 5 条日历规则，打开 http://127.0.0.1:8080
go run ./cmd/kitewheel -demo -addr 127.0.0.1:8080

# 生产形态：落盘到 ./data，虚拟时钟从指定时刻起步
go run ./cmd/kitewheel -addr 127.0.0.1:8080 -data ./data -now 2026-09-18T00:00:00Z

# 自定义各层格子数与跨度（必须逐层满足“上层一格 = 下层一整圈”）
go run ./cmd/kitewheel -levels 60s,60m,24h,31d -data ./data
```

`-snapshot-every N` 控制多少条日志做一次快照并轮转日志。

## 对照验证

```bash
go test ./...            # 全部（含约 70 万条消息的逐条差分比对）
go test -short ./...     # 跳过几十万条规模的大用例
```

差分基准是一个独立的、只有最小堆的实现 `internal/refsched`，它完全不使用
时间轮几何，两侧共享的只有 `model.Key` 这个排序定义。`internal/sim` 生成
同一条操作流分别喂给两边，逐条比对投递的 **消息号、到期时刻、投递时刻、
是否过期补发**，任何一步不一致立即报出是第几个操作、第几条投递。

## 设计要点

### 分层时间轮（需求 1、3、4）

层从细到粗：秒（60 格 × 1s）、分（60 × 1min）、时（24 × 1h）、天（31 × 1d）。
每层的格子数和跨度都可配置，但必须满足**上一层一格恰好是本层一整圈**
（`Span(l+1) = Len(l) * Span(l)`），否则同一时刻可能落进两个层，顺序就不确定了。

- 一条消息放在**能装下它的最细一层**（相对当前时钟）。
- 某一层的格子到点时，把整格消息按同一规则重新分配到下层。
- 层边界时刻归**更细的层**：`due - now < Horizon(l)` 才放第 l 层，严格小于，
  所以正好落在边界上的消息不会早一格也不会晚一格（需求 4，`TestExactBoundariesAcrossLevels`）。
- 时钟只走到“下一个真正有事发生的时刻”：最早的非空粗层格子起点、最早的 0 层到期、
  最早的日历物化时刻，三者取最小。空格从不逐格推进（需求 3）。
  跨 20 天的空转只产生每层一次的降级（`TestIdleMonthsAreCheap`）。

### 顺序（需求 2）

所有消息最终都落在 0 层，0 层投递时在最多 60 个格子中按统一的 key 取最小：

```
到期时刻 → 优先级高者先 → 实时消息先于周期消息 → 规则创建序号 → 出现序号 → 插入序号
```

- 同一时刻先看优先级，再看加入先后。
- 插入序号在每次入队/改期时分配，绝不复用；改期相当于在新时刻重新加入。
- 降级时每个格子都是有序的归并，所以“各层之间降级重排后顺序不变”
  不是靠运气，而是靠每一跳都保持 key 全序（`TestOrderingSameInstant`、
  `TestFestivalNightBurst` 对 30 万条同秒消息逐条校验顺序）。

### 取消与改期（需求 5）

按消息号取消、按消息号改期。每条消息有两个身份：

- `Seq`：插入顺序，改期后重新分配；
- `UID`：实例身份，每次改期换新。

格子按 `UID` 记录成员，被取消或改期掉的旧版本即使还躺在某个尚未重排的格子里，
也永远不可能被投出去。改期跨层就是“从旧格子摘除 + 按新到期时刻重新选层”。

### 过期消息（需求 6）

到期时刻不晚于当前时钟的消息立即投递；**严格早于**当前时钟的另外计数
（`past_due`），页面上单列“过期补发”。`due == now` 算准时，不算过期。

### 大跨度拨钟（需求 7）

一次拨快几天时，事件按时间先后逐级处理：物化 → 从最粗层开始逐层降级 →
0 层按 key 投递。因为每一层的格子用**绝对起点**标识（不是取模的槽位号），
一次拨钟跨过多圈也不会把上一圈的同号格子混进来，不漏投也不重投
（`TestLargeClockJumps`、`TestMultiDayJumpCascadesEachLevelInOrder`）。

### 周期规则（需求 8）

`internal/calendar` 支持：

| 类型 | 示例 |
|---|---|
| `dates` | 指定若干日期（共用同一时刻），如放飞日 |
| `monthly_day` | 每月 31 日 |
| `monthly_nth_weekday` | 每月最后一个周六、第 2 个周三 |
| `monthly_nth_workday` | 每月第 3 个工作日（可配节假日），`nth = -1` 为最后一个 |

规则有一个**事件时刻 + 偏移**：`offset_sec = -1800` 就是“开场前半小时”。
月份按规则创建当月起算，所以某个月被跳过不会让后面的序号错位。

缺日策略可配：这个月没有 31 号时，`skip` 跳过或 `clamp` 落到月末；
第 5 个周几/工作日不存在时同理回落到当月最后一个。
闰年二月、2100 年这种非闰年世纪年都有逐条用例（`internal/calendar/*_test.go`）。

周期消息在到期前一个最粗层跨度（默认 31 天）就被物化成普通消息，之后走
和实时消息完全相同的降级与投递路径，所以顺序、取消、改期、大跨度拨钟对它们
一视同仁。日历出现的编号是确定的 `规则号#序号`。

### 落盘（不怕重启）

- **写前日志**：每条入队、改期、取消、规则增删、拨钟都先按
  `kind(1) time(8) len(4) payload crc32c(4)` 追加到日志，再落地到内存；崩溃留下的
  半条尾巴会被识别并截断，文件中段的损坏会报错而不是悄悄丢历史。
- **快照 + 分代**：桶按 `gen-N` 目录写、清单 `MANIFEST` 最后原子改名，
  任何时刻崩溃都只会看到“旧清单 + 完整旧日志”或“新清单 + 空新日志”。
- **状态是日志的纯函数**：同一套日志重放得到逐字节一致的投递流
  （`TestRestartMidRun`、`TestRestartAfterSnapshot`、`TestReplayDeterminism`）。
  恢复时先读快照再重放日志尾，时钟、待投递集合、计数器都与重启前一致。

### 规模实测

`TestFestivalNightBurst` 是本项目要解决的问题原样复现：30 万条消息的到期时刻
全部落在同一秒内，时钟从一天前一步拨到那一刻。

```
enqueue 300000 messages: 135ms
deliver:                 440ms
```

`TestHalfMillionSkewed` 用约 52 万条到期时间严重不均的消息、24 条周期规则、
5 天级拨钟，与最小堆参考实现逐条比对，约 8 秒跑完并全部一致。

### 页面

单页，无构建步骤（`internal/server/web/index.html`，`go:embed` 打包）：

- **分层时间轮**：每层画成以当前指针为起点的格子窗口，按格内条数着色，空格标“跳过”；
- **即将到期**：按投递 key 排序的前若干条；
- **已投递**：最近投递，标注实时/周期、是否过期补发、晚了多久；
- **周期规则**：规则说明、锚点月份、下次活动与后续几次预览，可增删；
- **统计**：投递、过期补发、入队、取消、改期、降级次数、空转跳格与累计跳过时长。

顶栏可 `+1分/+1时/+1天/+7天` 或任意秒数拨钟、直接“拨到下一条”，
并可插入消息、按消息号取消/改期。

## 目录

```
cmd/kitewheel        入口：页面 + 虚拟时钟 + 演示数据
internal/wheel       层几何：绝对格位、层选择、边界判定
internal/model       消息与投递 key（全序）
internal/engine      调度状态机：降级、投递、规则物化、快照
internal/calendar    周期规则计算（独立、可单测）
internal/store       日志、快照分代、桶文件
internal/refsched    独立的最小堆参考实现
internal/sim         差分生成器与全部对照用例
internal/server      HTTP API + 页面
```
