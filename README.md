# 风筝节 · 延时消息调度服务

为风筝节电子票场景写的延时消息服务：入场提醒、退票截止、放飞场次提醒这类定时消息，
用**分层时间轮**调度，消息落盘不怕重启，自带一个调度看板页面。
彻底解决数据库轮询在"节前一晚几十万条同时到点"时扫表慢、提醒晚二十分钟的问题。

## 运行

```bash
go build -o bin/server ./cmd/server
./bin/server -addr :8080 -data ./data/ops.log          # 真实时钟
./bin/server -virtual -speed 3600 -demo 200000        # 虚拟时钟 ×3600，20 万条演示数据
```

看板：http://localhost:8080/ —— 分**各层时间轮、即将到期、已投递、周期规则、统计**五块，
可直接在页面上添加消息、取消、改期、确认。

## 设计要点

1. **四层时间轮**（秒 60 格 / 分 60 格 / 时 24 格 / 天 366 格，每层格子数与每格跨度均可配）。
   高层格子到点时把格内消息降级到下层重新分配（级联）。
2. **到期误差按层统计**：秒层按每条消息记（投递时刻 − 截止时间），高层按每次级联记
   （级联时刻 − 格子到期时刻），看板给出各层平均、最大提前、最大延后。
3. **空转跳格**：所有层的非空格子放在同一个最小堆里，拨钟时直接跳到下一个非空格，
   连续空格完全不经过；几十万条消息稀疏分布在 7 天上也能秒级拨完。
4. **边界精确**：全部用整毫秒对齐运算，截止时间正好等于 `当前指针 + 层跨度` 的消息
   进入上一层而不是硬塞进本层最后一格，不会提前或推后一格
   （`wheel.TestBoundaryExact` 有针对性用例）。
5. **取消与改期**：按消息号操作；改期用代际号（gen）作废旧的时间轮项，
   跨层迁移不会重复投递。
6. **过期即投**：添加/改期时截止时间已过去的消息立即投递，单独计数（统计卡"过立即刻投递"）。
7. **日志压紧**：所有写操作先追加到操作日志（JSON 行）；日志增长到活消息两倍且超过
   阈值时自动重写，只保留**没到期**和**已投递未确认**的消息，也可看板手动触发。
8. **周期消息**：支持日历规则，如每个放飞日开场前半小时
   `{"daily":true,"time":"09:00","offset":"-30m"}`，也支持每周几、指定日期、
   偏移量、截止日期；规则写错（时间格式、选择器缺失/冲突、日期越界等）在添加时直接报错，
   每次触发后自动排下一次。

## HTTP API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 看板全量状态（各层 / 即将到期 / 已投递 / 规则 / 统计） |
| POST | `/api/add` | `{"payload":"...","delayMs":3600000}` 或 `{"payload":"...","rule":{...}}` |
| POST | `/api/cancel?id=` | 按消息号取消 |
| POST | `/api/resched?id=&deadlineMs=` | 改期（跨层自动迁移） |
| POST | `/api/ack?id=` | 确认已投递消息 |
| POST | `/api/compact` | 手动压紧日志 |

## 代码结构

```
internal/clock      真实/虚拟时钟
internal/wheel      分层时间轮（级联、跳格、按层误差统计）
internal/store      追加式操作日志 + 压紧
internal/recur      日历周期规则（添加时校验）
internal/scheduler  调度器：轮 + 日志 + 取消/改期/确认 + 快照
internal/web        看板页面与 JSON API
cmd/server          服务入口（真实/虚拟时钟、演示数据）
```
